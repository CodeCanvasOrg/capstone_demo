HS Code Data Cleaning and Ingestion for Trade Classification

HumbleBeeAI consolidated fragmented HS code guidance and optimized 65.5 million product descriptions into a searchable data foundation for trade classification. [PDF p. 1]

Executive Summary

HumbleBeeAI’s Data Cleaning & Ingestion for HS Code Systems covers two related efforts: consolidating HS rules and code relationships scattered across PDFs, and cleaning a large catalog of product descriptions mapped to 10-digit HS codes. The work created structured data for customs officers, businesses planning international expansion, and developers building trade applications. The case study describes a working foundation for AI-powered classification; it does not provide a production deployment status for a specific end-user application. [PDF p. 2] [PDF p. 1]

Context and Challenge

HS codes shape tariffs, regulations, and product tracking in cross-border trade, but the source data was difficult to use consistently. Definitions, detailed code information, rules, and exceptions were spread across disconnected PDFs, sometimes with overlapping or conflicting information. Users had to search multiple files and manually cross-reference related codes; inconsistent formatting also impeded automation. Initial storage in separate databases required multiple queries and produced slow or incomplete retrieval. [PDF p. 2] [PDF p. 2]

A separate scale and quality problem affected a dataset of about 65.5 million product descriptions mapped to 10-digit HS codes. Repeated products appeared with small spelling, punctuation, or formatting differences, creating storage waste and search results dominated by near-duplicates. The size also made processing slow and resource-intensive, limiting the practicality of real-time applications. [PDF p. 2]

Solution and Capabilities

The work addressed both reference data and real-world product descriptions, combining data cleanup with structured storage and retrieval. The case study reports a dual-database approach using Pinecone for semantic search and MongoDB for structured access. [PDF p. 1]

Consolidated HS code guidance

Scattered HS information was organized into two structured Excel datasets: one containing 4-digit code definitions, redirections, rules, and clarifications, and another representing hierarchical relationships across the HS taxonomy. Row-by-row ingestion and unified indexes support consistent storage. Pinecone supports semantic searches based on natural-language product descriptions, while MongoDB supports structured queries and hierarchical browsing. [PDF p. 2]

Deduplication with product-frequency information

For product descriptions, the cleaning process lowercased text and standardized formatting, then used text analysis to identify entries that were effectively alike despite wording variations. Clustering grouped duplicates rather than simply discarding them, retaining counts of how often products appear in the trade data. The resulting unique descriptions were ingested into Pinecone for semantic search and MongoDB for structured storage. [PDF p. 3]

Results and Business Impact

The case study reports the following outcomes for the two projects: [PDF p. 3] [PDF p. 3]

  • Product-description dataset: reduced from 65.5 million records to about 2 million unique records, a reported 97% reduction, while retaining frequency counts to preserve product-popularity information. [PDF p. 3]

  • HS code lookup: users can retrieve complete information for a code through a single query rather than searching multiple sources; the case study says results that previously required manual searches through multiple PDFs return in seconds. [PDF p. 3]

  • Search and storage: the case study reports more diverse, representative search results instead of pages of duplicates, improved query performance, and lower storage costs after deduplication. It does not provide measured timings, cost amounts, or a quantified search-accuracy score. [PDF p. 3]

  • Application foundation: the integrated data is described as supporting AI and machine-learning applications that need clean, structured training data; specific downstream business outcomes are not quantified. [PDF p. 3]

The source does not report a measured reduction in customs processing time, tariff-calculation errors, or compliance incidents, so those business impacts cannot be quantified here.

Conclusion

These projects transformed fragmented HS guidance and highly repetitive product descriptions into structured, searchable datasets. The reported 97% reduction in product-description records and the consolidation of code information into single-query access demonstrate the data-engineering value described in the case study, while measured downstream business impact and production deployment status remain unspecified.
