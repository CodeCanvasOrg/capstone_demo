Excel-Based HS Code Testing Framework: 11,000 Descriptions in Four Hours

An Excel-based automated testing framework processed 11,000 product descriptions for HS code validation in approximately four hours. [PDF p. 1]

Executive Summary

HumbleBeeAI’s Excel-based automated testing framework helps organizations validate HS code classification systems against large datasets of product descriptions. It addresses a practical bottleneck: manual checking of 11,000 descriptions was estimated to take more than a month, limiting how often teams could run thorough tests. The case study reports the framework’s first run processed that dataset in about four hours using an Excel input and a FastAPI endpoint. [PDF p. 2]

The source describes the framework as delivered and reports a completed first run. It does not identify a named client or provide independently measured business outcomes beyond the reported processing-time comparison. [PDF p. 2]

Context and Challenge

HS code classification systems need validation across many product descriptions, categories and edge cases. In the previous workflow, subject matter experts reviewed each description, determined an appropriate code and compared it with system output. For a dataset of 11,000 descriptions, this manual work was estimated to require more than a month of dedicated expert time. [PDF p. 3]

The manual approach also made consistent, repeatable testing difficult: reviewer interpretation could vary, while fatigue and the lack of systematic documentation made it harder to trace error patterns or compare system versions. As a result, broad validation was costly and slow, and regular test cycles could be constrained by available time and resources. [PDF p. 3]

Solution and Capabilities

The framework keeps test preparation in a familiar spreadsheet workflow and automates processing and comparison behind the scenes. Its described capabilities include: [PDF p. 3]

  • Excel-based test input: users provide a standardized two-column file containing product descriptions and expected HS codes.

  • Automated classification and comparison: the FastAPI endpoint processes each row through the HS code classification system and compares system outputs with the expected codes.

  • Validation reporting and logs: the framework generates reports covering accuracy metrics, error patterns and performance statistics, and records processing activity for analysis.

  • Repeatable test cycles: the same Excel dataset can be run again to compare results across testing periods or system versions.

These capabilities are intended to make large-scale validation more consistent and to help teams examine classification errors and system changes without manually reviewing every entry. [PDF p. 3]

Results and Business Impact

The reported first run processed 11,000 product descriptions in approximately four hours. The source compares this with an estimated month or more for manual validation and reports a productivity improvement of over 180 times the previous manual approach. [PDF p. 3]

  • Test scale and time: 11,000 product descriptions processed in approximately 4 hours.

  • Comparison reported: more than a month of estimated manual validation versus approximately 4 hours of automated processing.

  • Reported productivity comparison: over 180 times the previous manual approach.
